1. Confirmed problem

Staff in the MLA office cannot keep contacts in one place. They cannot find a person by administrative area. They do not have a record of past talk and past promises.

The first version is a proof of concept. It must show the desk in a browser. Data must stay in that browser. It must not depend on a server database or on SMS.

The client confirmed rural and urban geography under Assembly Constituency. The client confirmed volunteer sign-up in the application. The client confirmed meetings with a document. The client confirmed area statistics, pin, notes, travel notices, and optional local requests.

2. Options considered

Option What we do Why we take it or leave it
A. Spreadsheets and paper No software. Teach a file naming rule. Leave it. It does not give area search, history, or public forms.
B. Browser POC (selected) One Next.js app. One store. localStorage. Sample geography. Staff and public switch. Take it. It lets the client see the desk. Cost stays low. It matches “it is a POC”.
C. Production system Login, shared database, SMS or WhatsApp, file store. Leave it for a later plan. It solves share and notify for real. It is not the confirmed first version.

Selected option: B. We did not pick B to look clever. The client asked for a POC in localStorage. We checked. The proposed limit is the right limit for this version.

How option B works (simple)

Think of one notebook in one drawer. The notebook is the store. The drawer is localStorage. Every screen reads that notebook. Writes go through store functions only. Geography is a tree. Each person has a geoPath. A filter on a parent area includes all child areas.

3. Blast radius

If this is wrong, how far does the damage spread?

StepWhat can break
The change itselfContact create, search, pin, notes, meetings.
One hop outGeography picker. If Assembly does not set in state, Rural and Urban stay closed. All forms that use GeoPicker fail.
Shared listsVolunteers, visits, and requests use the same geoPath and the same inArea helper. A bad match function breaks statistics and travel reach counts.
Role splitPublic users can open staff URLs. AppShell must hide those screens. This is a demo switch. It is not security.
StorageAll data is one JSON key: contact-app-poc-v1. A bad persist can replace good data with seed. Reset is a staff action with confirm.

Because the radius is the whole desk, we do not ship one feature in isolation. We keep one store and one GeoPicker. We do not add a second list of contacts.

Stage the work: store and geography first. Then search. Then history. Then the other lists. Do not start with travel SMS. The POC has no SMS.

4. Success criteria

Write these before the build. A criterion that names a button is not success. Success is what changes for the person.

  1. A staff user finds a sample contact by village or by municipal ward without help from another person.
  2. A staff user opens that contact and sees notes and meetings for that person, or sees an empty history that they can fill.
  3. A staff user pins a contact. The pin shows on the contact list and on the staff home.
  4. A public user submits a volunteer form. A staff user sees that person as pending and can accept the person.
  5. A staff user schedules a meeting, attaches a file under 400 KB, and opens that file again from the meeting list.
  6. A staff user picks a Block. Statistics count contacts that live in villages under that Block, not only contacts tagged with the Block id alone.
  7. A staff user publishes a travel notice for an area. Staff home and public home show that notice if the date is today or later.
  8. A public user submits a local request. A staff user can mark it reviewed.
  9. After a browser refresh, the same data is still there (same browser, same localStorage key).

Not in success for this plan: SMS delivery, multi-device share, real login, full constituency geography.

5. Tasks

Each row is small enough for a stranger to pick up.

# Task Done when
1 Add seed geography and seed contacts in src/data/seed.js. Include rural and urban nodes under one assembly. createSeedState() returns geoNodes and sample lists.
2 Add store in src/lib/store.js. Load and save contact-app-poc-v1. Merge onto seed. Persist only after ready. Refresh keeps data. Reset restores seed after confirm.
3 Add geo helpers in src/lib/geo.js: childrenOf, descendantIds, contactInArea, formatPath. A parent area match includes child areas.
4 Add GeoPicker. Clear child fields when a parent changes. Keep Rural and Urban disabled until assembly has a value. Always include a blank select option. Staff can pick rural or urban after assembly. The select and state stay in sync.
5 Add AppShell. Staff menu and public menu. Block public users on staff paths. Role key in localStorage. Public switch hides staff pages. Public can still open home, volunteer form, and request form.
6 Add contact search page. Filter by text, designation, and area. Pin from the list. Success criterion 1 and 3 for the list.
7 Add contact create and detail. Validate 10-digit phone. Notes add/remove. Show meetings. Link to schedule with contactId. Success criterion 2.
8 Add appointments page. Optional contact. Else geoPath. fileToDocument with 400 KB limit. Success criterion 5.
9 Add public volunteer form and staff volunteer list with accept. Success criterion 4.
10 Add stats page. Deepest selected area. Count with inArea. Success criterion 6.
11 Add visits page and show upcoming visits on home for staff and public. Success criterion 7.
12 Add public request form and staff request list with reviewed status. Success criterion 8.
13 Add staff home counts, upcoming notices, and pinned contacts. Home matches the store. No second data source.
